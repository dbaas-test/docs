# Платформа Nimbus DBaaS — обзор

## Что это

**Nimbus DBaaS** — внутренняя платформа крупной IT-компании, предоставляющая PostgreSQL
как управляемую услугу. Команды создают базы через портал, подключают приложения и работают
с данными. Инфраструктуру PostgreSQL, мониторинг, резервное копирование и доступность
обеспечивает команда DBaaS/SRE.

Пользователю не нужно администрировать сервер PostgreSQL: платформа сама разворачивает
экземпляр, следит за его состоянием и делает резервные копии.

## Основные сущности

| Сущность | Что это |
|---|---|
| **Database Instance** | Экземпляр PostgreSQL. Имеет идентификатор (например, `pg-orders`), версию, размер хранилища и набор параметров |
| **Database** | База данных внутри экземпляра. В одном экземпляре может быть несколько баз |
| **Database Owner** | Владелец базы: управляет схемами и ролями в пределах выданных разрешений |
| **Developer** | Разработчик приложения: подключает приложение и работает с данными |
| **DBaaS Support** | Первая линия поддержки: первичная диагностика и помощь |
| **SRE** | Команда эксплуатации платформы: устранение платформенных проблем |

## Роли и возможности

| Роль | Возможности |
|---|---|
| Developer | Подключение приложения, просмотр доступных ресурсов |
| Database Owner | Управление базой и пользователями в рамках разрешений |
| DBaaS Support | Первичная диагностика и помощь |
| SRE | Эксплуатация инфраструктуры и устранение платформенных проблем |

Владение базой и принадлежность к Developer — разные вещи. Владелец может управлять
объектами внутри базы, разработчик — только работать с данными в рамках выданных прав.

## Жизненный цикл Database Instance

1. **Создание** — команда оформляет заявку через портал Nimbus. Платформа разворачивает
   экземпляр PostgreSQL и выдаёт эндпоинт подключения.
2. **Наполнение** — владелец создаёт базы, схемы и роли.
3. **Эксплуатация** — приложения подключаются к эндпоинту. Платформа обеспечивает
   доступность, мониторинг и резервное копирование.
4. **Изменение** — параметры экземпляра и поддерживаемые расширения меняются через портал.
5. **Вывод из эксплуатации** — экземпляр удаляется по заявке. Данные удаляются безвозвратно.

## Границы ответственности

**Отвечает пользователь:**

- корректность SQL-запросов и схемы данных;
- настройка пула подключений в приложении;
- управление правами внутри своей базы в пределах разрешений;
- своевременное обращение в поддержку при деградации.

**Отвечает платформа (DBaaS/SRE):**

- доступность и работоспособность PostgreSQL;
- параметры экземпляра и обновления версии;
- резервное копирование и восстановление;
- мониторинг состояния баз;
- устранение платформенных проблем.

## Как обратиться в поддержку

Обращение создаётся в трекере поддержки по шаблону. В обращении обязательно указывается:

- **идентификатор экземпляра** — без него обращение невозможно связать с конкретной базой;
- описание симптома и когда он начал проявляться;
- что менялось перед появлением проблемы;
- масштаб влияния.

Обращение разбирается по эксплуатационной документации и данным мониторинга, после чего
попадает к дежурному SRE.

## Ограничения платформы

- Версия PostgreSQL и набор доступных расширений определяются платформой.
- Прямое администрирование сервера и доступ к файловой системе не предоставляются.
- Параметры экземпляра меняются через портал, а не через файлы конфигурации.
- Расширения, не входящие в поддерживаемый список, установить нельзя.
- Восстановление данных выполняется командой SRE по заявке.
- Планировочные работы выполняются в согласованные окна.
