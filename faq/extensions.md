# FAQ: расширения PostgreSQL

**Когда использовать этот документ**

Обращения вида:

- «Как включить `pg_stat_statements`?»
- «Почему расширение отсутствует в списке?»
- «Нужно ли перезапускать PostgreSQL после включения расширения?»
- «У меня нет прав на включение расширения»

## Что такое расширения PostgreSQL

Расширение — дополнительный модуль, который подключается к базе или к экземпляру и добавляет
функциональность: сбор статистики, дополнительные типы данных, функции для работы с ними.
Расширения бывают двух видов:

| Тип | Как подключается | Нужен перезапуск |
|---|---|---|
| Обычное | Командой подключения к базе | Нет |
| Предзагружаемое | Через параметр экземпляра | Да, требуется перезапуск экземпляра |

`pg_stat_statements` относится ко второму типу: оно загружается в память при старте PostgreSQL.

## Зачем нужно `pg_stat_statements`

Расширение собирает статистику выполнения запросов и позволяет понять:

- какие запросы выполняются чаще всего;
- какие запросы потребляют больше всего времени;
- какие запросы читают больше всего данных.

Это основной инструмент для поиска источника деградации производительности, поэтому запрос
на включение `pg_stat_statements` — одно из самых частых обращений в поддержку.

## Как проверить, включено ли расширение

Проверка выполняется пользователем самостоятельно и не требует прав администратора:

```sql
-- какие расширения подключены к текущей базе
SELECT extname, extversion FROM pg_extension;
```

Если `pg_stat_statements` в списке отсутствует — расширение не подключено к базе.
Отсутствие в списке не означает, что расширение недоступно на платформе.

## Как включить поддерживаемое расширение

1. Открыть страницу **Database Instance** в портале Nimbus.
2. Перейти в раздел **Extensions**.
3. Найти нужное расширение в списке (`pg_stat_statements`).
4. Проверить доступность расширения для текущего экземпляра.
5. Включить его, если операция доступна вашей роли.
6. Если операция недоступна — обратиться к **Database Owner** базы или в **DBaaS Support**.

Раздел **Extensions** показывает только расширения, поддерживаемые платформой для данной
версии PostgreSQL. Возможность включить расширение зависит от роли: **Developer её,
как правило, не имеет**, решение принимает Database Owner.

## Частые вопросы

### Нужно ли перезапускать PostgreSQL?

Для **предзагружаемых** расширений (к ним относится `pg_stat_statements`) — да. Параметр
предзагрузки применяется только при старте экземпляра. Перезапуск выполняет платформа
в согласованное окно; пользователь его не запускает.

Для обычных расширений перезапуск не нужен.

### Почему расширение отсутствует в списке?

Возможные причины:

- расширение не входит в поддерживаемый список платформы;
- расширение недоступно для текущей мажорной версии PostgreSQL;
- расширения нет для текущего типа экземпляра.

Если расширение есть в списке, но включить его не удаётся — это вопрос прав, см.
[permissions.md](permissions.md).

### Почему не хватает прав?

Включение предзагружаемого расширения меняет параметры всего экземпляра, поэтому требует
роли **Database Owner** и подтверждения от платформы. У роли **Developer** таких прав нет.

### Можно ли использовать расширение для анализа запросов?

Да, `pg_stat_statements` — основной штатный способ. Он даёт агрегированную статистику
по нормализованным запросам. Текст конкретного медленного запроса в реальном времени он
не показывает: для этого используются логи.

### Что делать, если расширение недоступно

Обратиться в поддержку через трекер, указав идентификатор экземпляра, нужное расширение
и задачу, которую требуется решить. Не все расширения можно включить — поддержка подтвердит
возможность или предложит альтернативу.

## Ограничения

- Установить расширение вне поддерживаемого списка нельзя.
- Доступа к файловой системе сервера нет: расширение нельзя «доставить» вручную.
- Включение предзагружаемого расширения требует перезапуска, то есть короткого простоя.
- Изменение параметров экземпляра доступно только через портал, и не во всех ролях.
